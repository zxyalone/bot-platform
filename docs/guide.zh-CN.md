# 使用指南

[← 返回首页](../README.zh-CN.md) · [English README](../README.md)

这里是 Bot Platform 每个功能的完整说明：怎么用、边界在哪、哪些事平台不保证。

## 运行

需要 Node.js 22.18 及以上（内置 TypeScript 和 SQLite），以及已登录的 agent 命令（`claude`、`codex`、`grok`、`agy`，用哪个装哪个）。不需要安装其他依赖。

```bash
npm start
```

然后打开 http://127.0.0.1:4317 。可以用 `PORT` 改端口，用 `BOT_PLATFORM_HOME` 改数据目录（默认是项目下的 `.data`）。

## 第一次使用

新的数据目录里没有任何 Bot。首页会检测这台电脑装了哪些 agent、是否已登录、各自能用哪些模型，并给出没装的那几家的安装和登录命令。装好后点“重新检测”。

- **团队按人适配：** “创建第一个工作空间”会把 Chief、Engineer、Reviewer、Scholar 分给这个人已登录的 agent。比如只装了 Codex，整个团队都用 Codex；装了三家以上，会默认加上 Scholar。创建前每个成员的模型都能改。
- **模型列表：** Grok 和 Antigravity 的可选模型来自它们自己的命令行输出，所以和每个人的套餐一致。Claude 和 Codex 用内置列表。新建或编辑 Bot 时可以选“其他模型…”，填任何这个 agent 支持的模型 ID。明显属于另一家的模型会被拒绝。
- **已有数据不变：** 已经有 Bot 的数据目录照常使用，不会被改动。

## Mac App

```bash
macos/build.sh             # 自己用：dist/Bot Platform.app，运行这个目录的代码和 .data
macos/build.sh --install   # 同上，并复制到 ~/Applications
macos/build.sh --release   # 给别人用：dist/release/ 下的 App 和 .dmg
```

需要 Xcode 命令行工具（`swiftc`）。App 是一个原生窗口，界面就是同一个网页：

- **两种构建：** 开发版运行这个目录里的代码，数据在项目下的 `.data`，改完代码重新打开 App 即可，项目目录移动后要重新构建。发行版自带一份代码和 Node（构建机上 22.18 以上最新的那个；如果它是通用二进制，App 也同时支持 Apple 芯片和 Intel），每个人的数据放在 `~/Library/Application Support/Bot Platform`。
- **后台进程：** 打开时先看端口上是不是自己的数据目录对应的平台：是就直接用，被别的程序或同一台 Mac 上别的账户占用就换下一个端口，没有就自己启动一个。Node 优先用 App 自带的，否则在系统里找 22.18 以上最新的版本。agent 命令按登录 shell 的 PATH 查找，所以装在 nvm、Homebrew 或 `~/.local/bin` 里都能找到。日志在 `~/Library/Logs/BotPlatform/daemon.log`，菜单里可以直接打开。
- **退出：** 默认会停掉自己启动的后台进程。定时任务要在后台进程运行时才会触发，需要的话在 App 菜单里勾选“退出后保持后台运行”。如果后台进程不是 App 启动的，退出时不会动它。
- **系统集成：** 通知走 macOS 通知中心，下载保存到“下载”文件夹并在 Finder 中显示，外部链接用默认浏览器打开。⌘R 重新载入，⌘= / ⌘- 缩放。

### 分发给别人

发 `dist/release/` 里的 `.dmg`。对方打开后把 App 拖进“应用程序”，第一次打开时会看到上面的检测页面。

- **签名：** 默认只做本地签名，别人第一次打开会被 macOS 拦下，需要在 Finder 里右键 App 选“打开”，或在“系统设置 → 隐私与安全性”里允许。如果有 Apple Developer ID，可以签名并公证，这样就不会被拦：

  ```bash
  DEVELOPER_ID="Developer ID Application: 你的名字 (TEAMID)" NOTARY_PROFILE=你的配置名 macos/build.sh --release
  ```

  `NOTARY_PROFILE` 是事先用 `xcrun notarytool store-credentials` 保存的凭据名。
- **对方需要：** macOS 12 以上，以及至少一个自己登录的 agent 命令。不需要装 Node。
- **安全边界：** 接口只监听本机，并校验 Host、Origin 和请求类型，网页无法跨站调用。同一台 Mac 上的其他账户仍能访问本机端口，多人共用一台电脑时要注意。

## 测试

```bash
npm test
```

```bash
npm run test:live
```

`test:live` 会调用真实的 Claude Code、Codex、Grok Build 和 Antigravity，消耗少量额度。每家都用最便宜的模型，列表在 `test/live/cheap.ts`。

## 结构

- `src/daemon/adapters/`：把 Claude Code 的 `stream-json` 和 Codex 的 `app-server` 协议统一成同一组事件。Codex 的 `app-server` 目前标记为实验性，升级 Codex 后要重跑 `test:live`。
- `src/daemon/engine.ts`：对话和回合的状态、审批、中断、重启恢复。
- `src/daemon/server.ts`：本机 HTTP 接口和事件流。只监听 127.0.0.1，并拒绝其他网站发来的请求。
- `src/daemon/store.ts`：SQLite 存储。归档只是隐藏，不会删除数据。
- `src/web/`：无构建步骤的前端页面。

## 行为说明

- 一个对话的底层 agent、路由和工作目录在创建时固定。之后改 Bot 的模型、强度或职责，会在下一条消息时生效。
- 权限设为“每次询问”时，Codex 连只读命令也可能要确认。觉得频繁可以改成“自动改文件（工作目录）”。这个模式下，Codex 的沙箱还允许写系统临时目录；写到其他位置会被拦下或询问。
- 群聊必须 @ 成员才会触发回复。一次 @ 多个时依次回复，Bot 的回复里写 @ 不会触发别人，要协作请用总线工具。
- Bot 通过 `list_bots`、`ask_bot`、`assign_task`、`get_task` 互相调用，共用调用方的工作目录。被调用方的审批卡会出现在你正在看的对话里。
- 单轮限制：调用深度 3 层、调用 10 次、同时进行 3 个，不能调用自己或调用链上已有的 Bot。
- 和单个 Bot 的对话没有每轮预算，只有项目预算能拦住它，而项目预算默认不限，请按需在右侧面板设置。群聊仍有每轮预算：按一条用户消息引发的整个调用树计算，只算未缓存的输入和输出，超出后整条链自动暂停，再发一条消息会开始新的一轮。
- Chief 权限为只读，新建工作空间时默认用 Sonnet（较早版本预置的 Chief 用 Opus，可以在顶栏的模型按钮里改）。它只能提议新建或修改 Bot，你批准后才生效。群聊里有 Chief 时，没有 @ 任何人的消息会交给它。
- 记忆放在 `.data/memory`，每个 Bot 和每个工作目录各一个 Git 仓库，可以在右侧面板查看、修改和回滚。启动 agent 时每份最多读入最近 3000 字，并标明只是参考资料。
- Bot 用 `isolated` 在工作树里工作，工作树放在 `.data/worktrees`，基于仓库当前分支的最新提交，未提交的改动不会带进去。合并由你在右侧面板操作，原仓库有未提交改动时会拒绝，有冲突时会撤销合并并保留工作树。
- 模型可能谎报完成。工作树任务结束时，平台会用 Git 检查实际改动，并附在回答末尾。
- 额度数据优先来自本机运行的 Magpie（`/v1/magpie/quotas`），能看到它管理的所有订阅。Magpie 没开时只能读到 Codex 的官方额度。
- “AI 完善”用 Sonnet 低强度做一次无工具调用（Claude 不可用时改用 Codex Luna），会消耗少量 token。
- Grok Build 和 Antigravity 走 ACP，权限由平台统一判断：只读模式拒绝一切写入和命令，未知类型的工具按写入处理。它们的角色说明随每次启动后的第一条消息发送。用量要到一轮结束才知道，所以这两家的预算只能在一轮结束后检查，不能中途打断。
- 费用是 agent 上报的估算值。使用订阅时不一定等于实际扣费。

## DeepSeek（dsh）

通过 DeepSeek Harness 的命令行 `dsh` 接入，协议和 Grok、Antigravity 一样是 ACP。平台会在 PATH 里找 `dsh`，找不到时用 `/Applications/DeepSeek Harness.app` 里自带的那个。

- **两种用法：** dsh 里登录 DeepSeek 账号，或者填 DeepSeek API key，平台都能用。模型名写成 `提供方/模型`，例如 `deepseek-account/deepseek-v4-pro`（账号）和 `deepseek-official/deepseek-v4-pro`（API key），界面上显示为“V4 Pro · 账号”“V4 Pro · API”。列表是平台启动 dsh 握手时读到的，只列出你这台电脑上 dsh 已经配好的那些，握手不会调用模型。
- **强度：** 低、中、高分别对应 dsh 的 low、high、max。
- **不经平台审批：** 实测 dsh 会直接写文件、运行命令，不向平台请求批准，只读 Bot 也一样。平台启动它时总会设置 `DSH_PERMISSION_MODE`（只读 Bot 用 `read-only`，其余用 `workspace-write`），但在我们测试的那份 dsh 上这个设置没有生效。所以对 DeepSeek Bot：权限选项和审批卡片都不起作用；派给它的后台任务（`assign_task` 和执行计划里的步骤）默认放进独立的 Git 工作树，合并前请在结果卡片里看改动；目录还不是有提交的 Git 仓库时，任务直接在原目录运行；私聊和 `ask_bot` 提问仍在原目录运行，不会隔离。
- **用量：** dsh 不报告 token 数，只报告每次请求后上下文有多大。平台把这些读数加起来当作输入，把其中最大的一次当作未缓存部分，输出记为 0。这只是估算，预算会按它计算，可能和 DeepSeek 实际扣费不同。
- **会话：** dsh 支持恢复会话，进程空闲回收后会接着原来的会话。

## 导出、备份和恢复

- **导出对话：** 右侧面板，生成 Markdown。工具调用只列名称和状态，不含输入输出；Bot 之间调用的中间过程只留问题和回答。
- **打包实验：** 实验工作台每一行的“打包”，含代码版本（提交号和 `code.diff`，以及还原命令）、配置、日志、指标、结果文件和所有最终评估。**包含测试集结果**，分享前请想清楚。结果文件超过 500 MB 时不打包，并写明。
- **备份项目：** 右侧面板，含项目说明、Bot 配置、所有对话（Markdown 和 JSON，包括已归档的）、任务、记忆、结果卡片保存的改动、附件和实验记录。**不含工作目录**，代码请用 Git。这份备份用来查阅和留存，**不能导入回平台**。
- **下载数据库：** 设置的“数据”页。要整体恢复时，停止服务，用它替换数据目录里的 `platform.db`，再启动。数据库不含记忆、实验文件、结果快照和工作树，它们在数据目录里，要一起留的话直接复制整个 `.data`。这个恢复步骤目前只能手动做。
- **恢复归档：** 设置的“数据”页列出归档的 Bot、群聊和对话，可以恢复。对话所属的 Bot 或群聊还在归档时，要先恢复它们。同名的 Bot 已经存在时不能恢复。

备份和导出都是明文，里面可能有你的代码片段、对话内容和实验数据。

## 可编辑的执行计划

复杂任务 Chief 会先提一个计划，卡片会出现在对话里，也进待办。简单任务它会直接做，不会多问；是否算复杂由它判断，你也可以直接要求“先给我看计划”。

- **能改什么：** 每一步的负责人、内容、验收条件、依赖、是否放进工作树，可以调顺序、删除、添加，也可以一键设为依次执行。保存前会检查负责人存在、依赖不成环、不超过单轮调用次数，有问题就留在卡片上。
- **怎么决定：** “批准并开始”按依赖派出任务，它们会进任务中心，受预算、并发和超时限制。“要求修改”把你的意见交回 Chief 重写，“拒绝”就不做。决定之前什么都不会开始，这一轮结束或被停止时计划失效。
- **顺序和依赖：** 显示顺序不决定执行顺序，没有依赖的步骤会同时开始，超过“同时进行”上限的步骤排队等空位，不会被拒绝。在同一个目录改文件的步骤，要么设依赖，要么放进工作树。
- **验收条件：** 会写进任务，要求负责人逐条说明，Chief 也会被要求核对。平台不会自己判断是否满足，那只是模型的说法。实际改动请看结果卡片。
- **旧的 Chief：** 工具的说明里写了什么时候用它，所以已有的 Chief 也能用。默认职责里的这一条只对新建的 Chief 生效，改过职责的不受影响。

## 被调用记录

Bot 被其他 Bot 调用时用的是单独的会话，不在你和它的私聊里。选中一个 Bot，在它的对话列表下面或右侧面板可以打开“被调用记录”，看谁让它做了什么、结论和完整过程，也能跳回发起的对话。这只是查看：它在私聊里仍然不记得这些事，要接着做就回到发起的对话，或者把结论贴给它。

## 工作空间

左侧顶部可以切换工作空间，点旁边的 `+` 新建。只填名称就能创建：目录默认放在 `~/BotWorkspaces/` 下，并初始化 Git、做一次空提交，这样工作树马上能用。也可以填已有目录；目录里已有文件时，平台不会替你提交，要你提交一次后才能用工作树。

- **团队：** 每个工作空间有自己的 Chief，默认再加 Engineer 和 Reviewer，可以选 Scholar，也可以改模型。默认 Chief 用 Sonnet，比默认工作空间的 Opus 便宜。
- **隔离：** 不同工作空间的 Bot 互相看不到，也不能调用，名字可以相同。群聊成员要在同一个工作空间。Chief 新建的 Bot 留在自己的工作空间。
- **共享的部分：** 全局设置、订阅额度、全局并发上限、待办、任务中心和搜索跨工作空间。点进别的工作空间的条目会自动切过去。
- **原来的 Bot：** 都在“默认工作空间”里，行为不变。
- **还没有的：** 工作空间不能改名或归档。

## 项目工作台

项目就是工作目录。左下角“项目”或右侧面板进入，可以切换项目。

- **做到哪了：** 上次打开以来发生了什么（几轮对话、失败、任务、改动的文件、实验、花费），以及现在在做什么。这些都来自平台记录，打开页面不调用模型，也不花额度。它不会告诉你事情做得好不好。
- **项目说明：** 写目标、约束和当前决定、参考资料。这个目录下的所有 Bot 从下一条消息开始都会读到，包括在工作树里干活的。Bot 不能改。参考资料是文字，Bot 要自己去读，平台不会替它打开。写得长会增加每次的 token。
- **其他：** 集中显示等你处理的事、参与的 Bot 和群聊、进行中的任务、最近的结果卡片和没合并的工作树、预算和实验，点进去就是对应的页面。

## 独立比较

在群聊的输入框写好问题，点“独立比较”，选参与的 Bot（2 到 6 个）和归纳者。适合调研、方案选择和代码审查。

- **独立的含义：** 每个 Bot 开新会话，只收到这个问题和附件路径，看不到彼此的回答和之前的群聊。调用其他参与者会被拒绝。它们读的是同一个工作目录，所以如果 agent 自己的全局记忆或工具结果相同，答案仍可能相似。
- **只读：** 回答和归纳都强制只读，不能改文件。Claude Code 只读时不能运行 Bash，所以需要跑命令才能回答的问题，可能答得不完整。
- **花费：** 大约是单次回答的“人数 + 1”倍，并且每个 Bot 都是新会话，没有缓存可用。这些都计入这个群的每轮预算和项目预算，用完就停。同时运行的数量受“同时进行”和全局上限限制，超出的排队。超时和后台任务相同。
- **归纳：** 由你选的归纳者生成“一致的地方、分歧、只有部分提到”，这是模型的概括，平台不核实。归纳者如果也是参与者，可能偏向自己，所以可以选没有参与的成员。原始回答始终显示。少于 2 个回答成功时不归纳。
- **追问：** 分歧下每个看法旁边有“追问”，会在输入框写好一句 @ 它的话，由你确认后发送。之后的群聊消息能看到这次比较的问题和回答。
- **限制：** 单个失败的回答不能单独重试，可以再发起一次。这些回答不进任务中心，也不能单独取消，要停就停整轮。

## 附件和产物

把文件拖进输入框、粘贴或点回形针，每个不超过 50 MB，一条消息最多 10 个。文件会复制到工作目录的 `.bot-attachments/`，再把路径告诉 Bot，它用自己的工具读取。派到工作树的任务也能用同样的相对路径读到。能不能读懂图片和 PDF 取决于 agent 和它的工具，平台不保证。在 Git 仓库里，这个目录写进了 `.git/info/exclude`，不会被提交，也不会算成 Bot 的改动。没发出去的文件一天后清理。

结果卡片或右侧面板可以打开“产物和附件”页，按对话或项目查看。

- **产物是什么：** 一轮里 Git 看到变化的文件、工作树里的改动；不在 Git 里时，是工具上报且在工作目录内的文件。实验结果仍在实验工作台。同一个文件只留一行，指向最后改它的一轮。工作树合并后，记录跟着文件移到主目录，来源不变；工作树丢弃后，记录留着并标明“已随工作树丢弃”。
- **来源：** 工具上报过才写是哪个 Bot 的哪个任务改的。只有 Git 看到时，写“这一轮改的（没有工具上报是谁）”。
- **预览和下载：** 读的是文件现在的内容，改过会提示；固定的历史改动请看结果卡片的“查看改动”。图片和 PDF 可以直接看，文本文件不超过 1 MB 可以预览，其他只能下载。HTML、SVG 之类不会在页面里运行。
- **在访达中显示：** 只支持 macOS，只接受平台记录过的文件，用 `open -R` 选中，不会打开或运行。

## 搜索

左下角进入，或者按 ⌘K / Ctrl+K。可以搜聊天内容、错误、Bot 之间的调用和任务、结果卡片里的摘要和文件路径、实验和想法，并按类型、项目、Bot、时间和状态筛选。点结果会跳到原来的位置，实验和想法会打开实验工作台。

多个词用空格隔开，要全部出现才算匹配，不是模糊搜索。只显示最新的 50 条。搜不到的内容：已归档的对话、工具调用的输入输出、Bot 之间调用的中间过程（只搜问题和回答）、文件内容本身和测试集结果。

## 项目预算和通知

项目就是工作目录。同一份代码放在不同目录，算两个项目。右侧面板可以设总预算和每日预算，0 表示不限；也能看到花费最多的对话和任务。

- **算法：** 按未缓存的输入和输出 token 计算，包括这个项目所有对话、后台任务和重试，归档的对话也算。每日预算从本地时间零点算起，一轮算在它开始的那天。这一版之前的记录也计入，但当时进行中的回合可能没有写入用量。
- **用完之后：** 不再开新一轮，这个项目所有进行中的回合都会停下，不能再派任务，排队的消息留在输入框上方并写明原因，实验结束也不会唤醒 Bot，下次发消息时会告诉它。调高预算后可以继续。用到 80% 时提醒一次。
- **拦不住的部分：** 用量是 agent 上报后才知道的，一定会超出一点。Grok 和 Antigravity 要到一轮结束才上报，所以可能超出一整轮。
- **全局并发：** 设置里的“同时运行的 agent”限制所有对话加起来的回合和调用，默认 8。满了之后新消息会被拒绝，排队的消息和后台任务继续等，有空位时自动开始。主 Bot 等后台任务时不占调用名额，否则会互相等死，所以峰值可能略高。

窗口不在前台时，浏览器会提醒任务完成、失败、等你批准和预算快用完，点击跳到对应位置。标签页标题也会显示待办数量。第一次要在设置的“运行限制”里允许通知。页面关掉就收不到。你自己点停止的不提醒。可以在项目预算里静音某个项目。

## 定时任务

到点后平台把一段话作为新消息发给某个 Bot，比如“每小时看一下 train.log，有 NaN 或 loss 不降就告诉我”。

- **设置：** 在 Bot 详情的“定时任务”里新建，可以选“每隔 N 分钟”（至少 5 分钟）或“每天几点”，后者能只选工作日或某几天。也可以直接在对话里让 Bot 用 `routine` 工具自己设：Bot 设的间隔至少 15 分钟，每个 Bot 最多 10 个开启的任务，对话里会出现一条通知。
- **运行：** 同一个定时任务的结果都留在同一个对话里。上一次还没结束时，这一次跳过；Bot 被暂停时也跳过。电脑睡眠或平台关闭期间错过的，只补跑一次。每次运行都算用量，受项目预算限制。
- **管理：** 每个任务可以立即运行、暂停、编辑、删除，或跳到它的对话。

## 命令行

`bin/botctl.mjs` 通过同一套接口操作正在运行的平台，适合脚本和定时作业。运行 `npm link` 后可以直接用 `botctl`。

```sh
botctl list                                    # 列出工作空间和 Bot
botctl run Chief "汇总今天的实验结果" --workspace 肿瘤分割模型 --export today.md
botctl run Engineer "跑一下单元测试" --json     # 输出 JSON，便于脚本处理
botctl export <对话ID> --out chat.md
```

`run` 会等这一轮和它派出的后台任务全部结束，再输出最后一条回复。遇到需要批准的操作时，它会提示你去网页里处理，然后继续等。退出码：0 完成，1 失败，2 超时（`--timeout` 分钟，默认 60），3 用法错误或找不到 Bot，4 连不上平台。平台地址可以用 `BOT_PLATFORM_URL` 指定。

## 节省用量

一轮里 agent 每走一步都会把整段会话重读一遍。缓存能让重读变便宜，但仍会消耗订阅额度。所以会话越长，后面每一轮越贵。

- **用量明细：** 每轮结束的那一行会显示这一轮发了几次请求、最后一次请求的上下文有多大。Bot 详情里的“累计用量”会显示平均每轮请求数和最大上下文。
- **长会话换新：** 单次请求的上下文超过阈值（默认 15 万 tokens）后，下一轮会开新会话，只带上最近约 2 万字的对话，并提醒 Bot 需要细节时重新读文件。在 设置 → 运行限制 → 节省用量 里调整，填 0 表示关闭。Grok 和 Antigravity 不报告上下文大小，不受影响。
- **Claude 精简启动：** Claude Bot 默认不加载你个人的 Claude Code 设置、插件和技能，还会把每台机器各不相同的信息移出系统提示，方便缓存复用。实测每次请求的固定上下文从约 1.9 万降到约 1.3 万 tokens。项目里的 `CLAUDE.md` 和项目设置照常加载。需要个人配置时，打开“Claude 用我的个人配置”。
- **不误走按量计费：** 启动 Claude 时会去掉环境里的 `ANTHROPIC_API_KEY`，始终使用订阅登录。
- **Antigravity 用量：** 它上报的输入不含缓存读取，平台会补上。以前记错的记录在升级时修正。

## 运行中追加消息

Bot 回复时输入框仍然可用。回车把消息排队，这一轮结束后作为一条普通消息发出，有自己的一轮和预算；还没发出时可以撤回。这一轮被停止或预算用完时，排队的消息不会发出，会留在输入框上方，可以放回输入框。守护进程重启时也一样。

Claude Code 和 Codex 可以点“立即补充”（⌘/Ctrl + Enter），把消息并进正在进行的这一轮，计入这一轮的预算。Grok、Antigravity 和群聊只能排队。Codex 的 `turn/steer` 属于实验性接口；补充被拒绝时会改为排队，并显示提示。

## 状态和结果

输入框上方显示这一轮正在做什么：修改了几个文件、在跑哪条命令、在等谁，以及最后一次更新的时间。超过 2 分钟没有动静时会提示可能卡住，等你批准或等别的 Bot 时不算。文件数只统计工具明确上报的编辑；上报不了的 agent 显示工具名称。

一轮结束后，如果改过文件、建过工作树或运行过检查命令，会出现一张结果卡片；只回答问题不会出现。

- **改动来源：** 在 Git 仓库里，平台比较这一轮前后的 `git status` 和提交。这段时间你自己改的文件也会算进去，卡片上写的是“这一轮期间目录里的变化”。Git 看不到时才列工具上报的文件，并注明来源。
- **验证：** 只列平台记录到的测试和检查命令（如 `npm test`、`pytest`）及其退出状态。这说明命令跑过，不说明测试覆盖够了。Bot 的说法只算“自述”。
- **查看改动：** 显示这一轮结束时保存的内容，之后再改文件也不会变。保存完成前对话仍算在回复中，下一条消息、任务重试和实验唤醒都会等它，保存在 `.data/results`。新文本文件显示全文；超过 1 MB 的新文件只列路径、大小和类型；测试集目录里的文件不保存。比较的基准是这一轮开始时的提交，所以这些文件之前已有的未提交改动也会显示。
- **接受结果：** 只记下你看过并接受了，不会合并或提交。工作树仍在右侧面板合并。“稍后处理”把卡片放到待办底部，不计入数量；“无需验收”把它移出待办。这两个都不代表接受。

## 任务中心

列出所有未归档对话里用 `assign_task` 派出的任务，显示负责人、依赖、状态、等待原因和失败原因。记录存在 `calls` 表里，重启后还在。`ask_bot` 是同步调用，不算任务，仍然只在右侧的调用链里显示。

- **依赖：** `assign_task` 可以传 `depends_on`。依赖全部完成后任务才开始，并能看到依赖的结论；依赖没完成时，下游任务会失败并写明原因。排队的任务计入调用次数，开始后才占并发名额。没有依赖的任务在并发已满时仍然直接被拒绝。
- **同时派给一个 Bot：** 同一个 Bot 的会话一次只做一件事。派任务时它正忙，任务就排队，等它忙完再开始。`ask_bot` 有人在等回答，所以会被告知先等结果。
- **取消：** 只有你能在任务中心取消。进行中和排队中的任务都可以，确认框会列出会一起停止的子任务和依赖它的任务。取消只停这些，这一轮的其他任务继续，已经做的改动不会还原。
- **超时：** 默认 30 分钟，可以在设置里改，0 表示不限。Bot 用 `timeout_seconds` 只能设得更短。超时只停这个任务和它发起的调用，这一轮的其他任务继续。等你审批的时间不计入。
- **重试：** 只有你能发起（任务中心或错误卡片），Bot 不能。只能重试最新一次尝试。重试和 Bot 发起的调用走同样的检查：暂停、调用权限、循环、深度、次数、并发。审批也照常。依赖没完成时会拒绝，请先重试依赖。工作树任务接着用原来的工作树，已合并或丢弃的不能重试。每次尝试单独记录，在列表里合并成一行。
- **重试占用的预算：** 这一轮还开着时，计入这一轮的次数、并发和预算。这一轮已结束时会新开一轮，和你再发一条消息一样：群聊用一份新的每轮预算，单个 Bot 的对话没有每轮上限。两种情况都计入项目预算；项目预算用完时不能重试。默认没有项目预算，这时反复重试的总花费没有上限。
- **结果怎么回到 Bot：** 这一轮还开着时，Bot 用 `get_task` 查旧的 `task_id` 也能拿到最新一次的结果。已结束的话，平台会在对话里加一条通知，下一条消息时交给 Bot，不会自动唤醒它花费额度。
- **一轮结束：** 没人取回的任务和这一轮一起停止，这一点没变，只是现在会写明原因。任务不会跨轮继续运行。
- **重启：** agent 进程会随守护进程一起退出，所以进行中和排队中的任务都标记为“已中断”，不会自动恢复。重试时会尽量恢复对方的 agent 会话。这一版之前的旧任务没有调用链记录，不能重试。
- **已知限制：** 用量在结束时才写入数据库，守护进程崩溃或重启时，这一轮和被中断任务的用量会偏低。

## 失败恢复

错误卡片上有三个按钮。Chief 暂停 Bot 的提示不是失败，没有这些按钮。

- **重试这一步：** 失败的是后台任务时，和任务中心的重试是同一个操作。失败的是一轮对话时，平台把原来的请求和失败原因作为一条普通消息重发，预算、审批和“还在回复中”的限制都和普通消息一样。这一轮已结束时会占用一份新的每轮预算。群聊里只重跑这一轮失败的成员。
- **不能重试的情况：** 错误之后你已经发过新消息；这一步不是你的消息发起的（比如实验结束后平台唤醒 Bot）；失败的是 `ask_bot` 提问，结果已经交回给提问的 Bot。这些情况可以用另外两个按钮。这一版之前的旧错误也没有重试按钮。
- **换 Bot 接手：** 和选中的 Bot 新开一个对话，用它自己的工作目录和审批。发给它的内容包括原来的请求、失败原因、上一位最后说的话（标明没有核实）和平台记录到的改动，并说明上一位的会话上下文没有带过来，要先检查现状。工作目录不同时会明确说看不到上一位的改动，选择时也会提示。已暂停的 Bot 也能选，因为暂停只限制其他 Bot 调用它。
- **补充信息：** 只是往输入框里加一行开头，原来的草稿保留，由你写完再发。

## 实验工作台

在右侧面板开启后，Bot 多出 `add_idea`、`update_idea`、`list_ideas`、`run_experiment`、`list_experiments`、`get_experiment` 这几个工具。关闭时这些工具不会发给 agent。

- **运行：** `run_experiment` 要你批准，然后在后台独立运行，守护进程重启也不受影响。结束后平台用指标唤醒对话（可以在设置里关闭）。默认在本机运行，也可以在设置里添加 SSH 计算目标。
- **记录：** 平台自动记录代码版本、配置和种子。有未提交的改动时，`code.diff` 同时包含改动和新建的文件（被 `.gitignore` 忽略的除外），可以在对应提交上用 `git apply` 还原。超过 5 MB 的新文件不进快照，只在 `code.json` 里记下大小和哈希，并标记“快照不完整”；测试集目录里的文件不进快照。
- **汇总：** 名称、类型、想法、命令、配置和代码版本都相同的运行才会放在一起算均值和标准差，数据划分请写在配置里。同一个种子重复运行只算一个样本，取平均。没写种子的运行各算一个样本。脚本往工作目录写未忽略的文件会让下一次运行变成新版本，结果文件请写到 `BOT_ARTIFACTS_DIR` 或加进 `.gitignore`。
- **想法账本：** Bot 只能建议判定，想法是否成立由你确认。
- **测试集闸门：** 最终评估只能由你在界面上发起，结果不会告诉 Bot，每次都会计数。每次评估有独立的目录（`final/<编号>/`），界面显示最近一次的结果。这是防误用，不是硬隔离：能读文件的 agent 如果自己找到路径，平台拦不住。

训练脚本的约定：

| 环境变量 | 用途 |
|---|---|
| `BOT_METRICS_FILE` | 把指标写成 JSON 数字，例如 `{"dice": 0.81}` |
| `BOT_CONFIG_FILE` | 读取配置 |
| `BOT_SEED` | 随机种子 |
| `BOT_ARTIFACTS_DIR` | 放结果文件 |
| `BOT_TEST_DIR`、`BOT_TRAIN_RUN_DIR` | 仅最终评估时提供 |

要在“结果”页对比分割结果，在 `BOT_ARTIFACTS_DIR` 写一个 `manifest.json`，图片用 PNG、JPG 或 WebP（路径相对于这个目录）：

```json
{"cases": [{"id": "case-1", "image": "cases/1_img.png", "label": "cases/1_gt.png", "pred": "cases/1_pred.png", "metrics": {"dice": 0.72}}]}
```
